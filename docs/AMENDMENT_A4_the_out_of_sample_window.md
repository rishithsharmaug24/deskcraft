## 3. The four parameters, and why each was about to be chosen by the wrong party

This is the third time in two days. `COST_HURDLE` was a threshold left for the package it scored
(A2). `ENB < 3.0` was a basis left for the package it scored (A3). **An OOS panel with no stated
end date, series list or vintage rule is the same defect with a much larger blast radius**, because
the parameter being chosen is *the sample the headline is computed on*.

### 3.1 The end date (DD98)

**`OOS_END = 2025-12-31`.** Chosen by a rule, not by taste: **the last complete calendar year at
the date of specification.** The specification date is 2026-09-16, so the rule yields exactly one
answer and there was nothing to pick — and it returns the same answer at 2026-09-15, the day this
was drafted, the first date it would return anything else being 2027-01-01 — the same defence §4.2 of A3 made for the basis, and it is the only defence
worth having.

Two things this refuses:

- **A window that ends "at extraction."** Then every re-extraction changes the OOS sample, and
  re-running the extractor until the numbers improve is a refresh rather than a violation. That is
  the attack surface, and it is closed by making the end a constant rather than a clock read.
- **A partial year in the headline.** Eleven complete years, equally weighted. A stub year
  aggregated beside full ones is not a window, and the 2026 stub is excluded by the rule that
  picked the date rather than by a judgement made after seeing it.

**Extension rule.** The window may be extended **only** at a complete calendar-year boundary, only
by amendment, and any extension is **reported as a separate window and never merged into a
published headline**. Re-scoring a landed verdict on a longer sample is a new result, not a better
one.

### 3.2 The size, which D14 asserted and nobody had measured (DD99)

§4's D14 row commissions *"~2,700 OOS days"*. Measured against this window: the DEV panel runs at
**260.89 sessions a year** (median 261, no holiday gaps), so eleven complete years is **≈ 2,870**
sessions. **D14's figure is 5.9% low**, and it was written against no stated end date at all —
2,700 sessions would end the window around **April 2025**, which is not a calendar boundary and
corresponds to no rule.

Annotated at the row, not rewritten, and **the estimate is labelled an estimate**: the true count
lands with the fixture, and D14's power table is computed on the count the fixture carries, not on
either figure in this document.

### 3.3 The series (DD100)

**The source register as it stands, and no additions.** A series added once results are visible is
a choice made with the answer in view, and the register is already an equality census for exactly
this reason. A series the OOS panel needs and the register lacks is a licence read first and a
panel change second — D3b's order of operations, which found that `GZ_SPREAD`'s licence had been
read three days earlier and nothing noticed until a package needed it.

### 3.4 The vintage rule, inherited rather than invented (DD101)

**An observation is carried only if a vintage dated on or before its own observation date exists.**
This is not new: **D3b refused five constant-maturity observations on exactly this ground**, their
only vintage being 2015-01-05, and recorded that *"a panel taking `obs_date` at face value would
have carried post-DEV knowledge in through a fixture nobody suspected."*

**The trap is strictly larger here.** On the DEV panel a stale vintage leaks knowledge across one
boundary. On an eleven-year OOS panel every observation has a revision history, and a panel built
from final values would let a risk-model backtest score itself against numbers that did not exist
on the day the model was asked to predict them. The rule transfers verbatim and the refusal count
is reported with the fixture.

## 5. What is enforced in code, not in prose

A2 fixed a threshold and A3 fixed a basis; both are constants a later package could read and
ignore. **This one is a type.** `FitWindow` already refuses an end past `DEV_END`; the symmetric
object refuses an OOS window that reaches back into the fit sample or forward past the fixed end.

```python
OOS_START = date(2015, 1, 1)    #: contiguous with DEV_END, no gap and no overlap
OOS_END = date(2025, 12, 31)    #: eleven complete calendar years, fixed before the panel exists
```

`OosWindow` refuses a start at or before `DEV_END`, a start before `OOS_START`, an end past
`OOS_END`, a backwards or empty interval, and a `datetime` where a `date` is required — the last
because `FitWindow` learned that a `datetime` subclass turns a bound into a `TypeError` by accident
rather than a refusal by design.

**So extending the sample is a code change and a red bar, not a keyword argument.** That is the
whole difference between a pre-registration and an intention.

**C96** holds the refusals and the contiguity: `OOS_START` is exactly the day after `DEV_END`, so
the two windows partition the record with no gap a package could quietly fit in. **C97** holds this
document against the module, in C90's shape, and recomputes the session estimate from the DEV
panel rather than trusting either figure written above.

## 8. What this could still get wrong

- **D14 and D15 run on the same eleven years, and D14 goes first.** Whatever D14 reports is known
  when D15's pre-commit is written, so D15's "out-of-sample" is out-of-sample for the *model* and
  not for the *analyst*. The look budget exists for this and this amendment does not touch it —
  but fixing the window does not fix the ordering, and nothing here should be read as though it
  did. **A holdout split would address it; inventing one is not this document's to do.**
- **`OOS_END` was fixed by a rule, and I knew what happened in those markets.** The rule yields one
  answer given the date, so the choice was not free — but the person applying the rule has read
  about 2020 and 2022, and that is true of every pre-registration written after the fact by
  someone who has lived through the sample. Stated, not solved.
- **The vintage rule is stated here and enforced in curvecast**, which this document cannot reach.
  C97 holds the specification; nothing on this side can hold the extractor to it until the fixture
  arrives and its refusal count can be read. **X13 is the only thing standing between the rule and
  a fixture that ignored it.**
- **Eleven years contains one crisis of each kind and not two.** 2020 and 2022 are both in the
  window, which is what D12's row wanted — and a sample chosen to contain the crises it will be
  judged on is a sample chosen. The rule picked the date, but the rule was written by someone who
  knew the window would contain them.
